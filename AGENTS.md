# AGENTS.md

Hackathon project ("Token God Indexes") for the Nansen Meridian Buildathon (Sep 22–28 2026). Bias toward a working demo over refactoring. `PLAN.md` is the day-by-day build plan; `CONDITIONS.md` has submission rules (1,000+ Nansen API calls, demo < 10 min).

## Structure

- `apps/api` — NestJS 12 backend, **ESM**, listens on **3001** (`PORT_API`)
- `apps/web` — Next.js 16 + React 19 + Tailwind 4 dashboard, polls API every 30s
- `packages/shared` — `@quant-board/shared` TS types; **not imported by either app yet** (web duplicates types in `apps/web/lib/api.ts`)
- `agents/*` — standalone Python tools (`daily_smta`, `token_god_mode`); **not** in the pnpm/turbo workspace
- `ARCHITECTURE.md` / `PLAN.md` describe Express + Next 14 — **stale**; the code is NestJS 12 + Next 16. Trust the code.

## Package managers are mixed — don't assume

Root declares `pnpm@9.5.0` + pnpm workspace + turbo, but there is **no root lockfile**. `apps/api` and `apps/web` each have their own `bun.lock` (web also pins `packageManager: bun@1.4.2`; api additionally has a stray `package-lock.json`). Installs were done per-app with bun. Run scripts from inside each app directory.

## Commands

Turbo at the root only defines `dev` / `build` / `clean` — there is **no** `turbo lint` or `turbo test`; run those per-app.

`apps/api` (scripts also work with `pnpm`/`npm run`):
- dev watch: `bun run start:dev`
- unit tests: `bun run test` (vitest, matches `**/*.spec.ts`)
- e2e: `bun run test:e2e` (separate config, matches `**/*.e2e-spec.ts`)
- lint: `bun run lint` — **oxlint** (type-aware), not eslint
- format: `bun run format` (prettier: single quotes, trailing commas)
- no typecheck script; `bun run build` (`nest build`) surfaces TS errors

`apps/web`:
- `bun run dev` / `bun run build` / `bun run lint` (eslint flat config)
- `next build` runs typechecking; **no test setup exists**

Python agents (`agents/daily_smta`, `agents/token_god_mode`):
- install: `uv pip install -e ".[dev]"` (or pip); each has its own `.env` from `.env.example`
- run: `python -m daily_smta` / `token-god-mode` CLI
- verify: `pytest -v` + `ruff check .` (config lives in each `pyproject.toml`: py311+, line-length 100)

## API quirks

- ESM + `module: nodenext`: **relative imports need explicit `.js` extensions** (e.g. `import { AppModule } from './app.module.js'`)
- **No dotenv / `@nestjs/config`** — env is read straight from `process.env`. Only Bun's automatic `.env` loading (when run via `bun run`) or exported shell vars work. Keys: `NANSEN_API_KEY`, `PORT_API` (3001), `CACHE_TTL_SECONDS` (300), `REBALANCE_THRESHOLD` (0.05). Never commit `.env`.
- Routes: `GET /api/index/current`, `GET /api/index/rebalance`, `GET /api/arbitrage/opportunities` (modules under `src/index`, `src/arbitrage`)
- Nansen access goes through `src/nansen/nansen.service.ts`; its in-memory call counter feeds the hackathon's API-call metric. Index data silently falls back to hardcoded tokens if Nansen fails.
- oxlint: `typescript/no-floating-promises` is error; `no-explicit-any` is off.

## Web quirks

- API base URL: `NEXT_PUBLIC_API_URL` ?? `http://localhost:3001` (`apps/web/lib/api.ts`)
- `apps/web/AGENTS.md` holds a block auto-regenerated by `next dev` — **do not delete it** (committing it keeps the tree clean). It points to `node_modules/next/dist/docs/` — Next 16 differs from older training data; read the local docs before writing Next code. `apps/web/CLAUDE.md` just imports it via `@AGENTS.md`.
